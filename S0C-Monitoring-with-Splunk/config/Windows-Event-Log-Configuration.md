# Windows Event Log Configuration

## Overview

Windows Event Logs provide important operating system and security telemetry for the Home SOC Lab.

In this project, Windows Security events were collected and analyzed using Splunk Enterprise. The main authentication events investigated were Event ID 4624 and Event ID 4625.

## 1. Windows Event Logs

Windows provides multiple event logs for different types of system activity.

The main log sources used in this project are:

* Windows Security Log
* Sysmon Operational Log

The Security log provides authentication and security auditing information.

The Sysmon Operational log provides detailed endpoint telemetry such as process creation.

## 2. Windows Security Log

The Windows Security log contains security auditing events generated by the operating system.

The Splunk sourcetype used for the Security log in this project is:

```text
WinEventLog:Security
```

A basic Splunk search is:

```spl
index=main sourcetype="WinEventLog:Security"
```

This allows the analyst to search Windows Security events collected by Splunk.

## 3. Successful Logon Monitoring

### Event ID

**4624 — An account was successfully logged on**

Event ID 4624 represents a successful authentication event.

The event can provide information such as:

* Account
* Logon Type
* Computer
* Process
* Timestamp
* Authentication details

A basic search is:

```spl
index=main sourcetype="WinEventLog:Security" EventCode=4624
```

## 4. Failed Logon Monitoring

### Event ID

**4625 — An account failed to log on**

Event ID 4625 represents a failed authentication attempt.

A basic search is:

```spl
index=main sourcetype="WinEventLog:Security" EventCode=4625
```

The event can be investigated using fields such as:

* Timestamp
* Account
* Logon Type
* Process
* Computer
* Event Code

## 5. Combined Authentication Monitoring

Successful and failed authentication events can be investigated together:

```spl
index=main (EventCode=4624 OR EventCode=4625)
```

This provides a combined view of authentication activity.

## 6. Failed Logon Investigation

The following search was used to investigate failed authentication events:

```spl
index=main sourcetype="WinEventLog:Security" EventCode=4625
| table _time ComputerName Account_Name Logon_Type Process_Name
| sort - _time
```

This search displays important fields for investigating failed logons.

## 7. Failed Logon Statistics

Failed authentication events can be grouped by account and logon type:

```spl
index=main sourcetype="WinEventLog:Security" EventCode=4625
| stats count by Account_Name, Logon_Type
```

This provides a summary of failed authentication activity observed in the lab.

## 8. Logon Types Observed

Different Windows logon types represent different authentication contexts.

### Logon Type 2

**Interactive logon**

This is associated with a user logging on interactively to the Windows system.

A controlled incorrect-password test generated a Logon Type 2 failed authentication event.

### Logon Type 3

**Network logon**

This is associated with authentication over the network.

A Logon Type 3 failed authentication event was also observed during controlled lab testing.

### Logon Type 5

**Service logon**

This is associated with a service starting under a Windows account.

A successful Logon Type 5 event involving the Windows SYSTEM account and the following process was observed during the investigation:

```text
C:\Windows\System32\services.exe
```

## 9. Controlled Failed Authentication Test

A controlled authentication test was performed on the Windows 11 VM.

### Test Procedure

1. The Windows 11 VM was locked.
2. An incorrect password was entered once.
3. The correct password was then entered.
4. The resulting Windows Security events were investigated in Splunk.

### Result

The incorrect-password attempt generated an Event ID 4625 event.

The activity was used to validate that failed authentication telemetry was being collected and could be investigated through Splunk.

### Important Limitation

Only one controlled incorrect-password attempt was performed.

Therefore, this activity was not classified as brute-force activity.

Repeated credential guessing was not performed in the lab.

## 10. Successful Authentication Investigation

A successful authentication event was also investigated.

### Observed Event

**Event ID 4624**

The observed service logon included:

* Logon Type: `5`
* Account: `SYSTEM`
* Process: `C:\Windows\System32\services.exe`

This event was treated as normal authentication telemetry within the lab environment.

## 11. Authentication Investigation Workflow

The authentication investigation process followed:

```text
Windows Authentication
        ↓
Windows Security Log
        ↓
Splunk Collection
        ↓
Event ID 4624 / 4625
        ↓
SPL Search
        ↓
Field Analysis
        ↓
Validation
        ↓
Documentation
```

The analyst can use this workflow to understand authentication activity occurring on the monitored endpoint.

## 12. SOC Relevance

Authentication telemetry is important because it can help analysts investigate:

* Successful logons
* Failed logons
* Account activity
* Interactive authentication
* Network authentication
* Service authentication
* Unexpected authentication patterns

Authentication events should be interpreted in context rather than automatically treated as malicious.

## 13. Detection Considerations

A single failed authentication event does not necessarily indicate an attack.

Analysts should consider:

* Number of failed attempts
* Time period
* Account involved
* Logon Type
* Source system
* Process
* Whether the activity was expected
* Related events

Repeated authentication failures may require additional investigation, depending on the surrounding evidence.

## 14. Relationship With Sysmon

Windows Security logs and Sysmon provide different types of telemetry.

### Windows Security Log

Provides security and authentication information.

### Sysmon

Provides detailed endpoint telemetry such as process creation.

Together they provide broader visibility:

```text
Windows Security Events
        +
Sysmon Telemetry
        ↓
      Splunk
        ↓
Detection & Investigation
```

## 15. Validation

Windows Event Log monitoring was validated by confirming that:

1. Security events were collected by Splunk.
2. Event ID 4624 could be searched.
3. Event ID 4625 could be searched.
4. Failed authentication could be generated in a controlled test.
5. Logon Type information could be investigated.
6. Authentication events could be analyzed using SPL.

## 16. Security Considerations

Authentication logs may contain sensitive information.

Before publishing screenshots or exported logs to GitHub:

* Remove passwords.
* Remove authentication tokens.
* Remove private information.
* Review usernames and hostnames.
* Review IP addresses where necessary.
* Crop or blur sensitive command-line values.

Do not publish credentials or secrets.
